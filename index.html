HOW IT WORKED

Core features built from scratch

Everything designed around privacy, zero identity pressure, and student life.

⏳

24h Content Lifecycle

Posts, chat bubbles, and stories expired after 24 hours. Optical blur applied as content aged, ensuring conversations stayed temporary and low-stakes.

🕯️

Hauwa Confession Board

A separate section for student thoughts, hostel memories, and campus questions categorized by tags with candle lighting in place of public likes.

🎬

Happy Watch Cinema

Students in different hostel rooms could join synchronized rooms to watch YouTube videos together with synchronized playhead states and live chat.

🔒

View-Once Media

Media sent in temporary chats could be marked as view-once. Photos self-destructed 5 seconds after opening with zero cloud retention.

📖

Department Yearbook

Anonymized directory filtered by academic departments (ICT, Design, Engineering) allowing students to track active streaks without revealing identities.

🎨

Custom Themes

Multiple dynamic color themes: Ghosted Orange (Warm Ember), Cosmic Purple, Aurora Teal, and Comic Panel styles to personalize the mood.

UNDER THE HOOD

Technologies used

FRONTEND

Flutter Web & Mobile (Dart)

Single codebase delivering cross-platform performance, custom CanvasKit dark-mode UI, and reactive state management.

DATABASE

Cloud Firestore

Real-time NoSQL database handling live feeds, direct chats, and synchronized room timestamps with sub-second listeners.

AUTHENTICATION

Firebase Auth

Domain verification locking access strictly to @adaniuni.ac.in campus accounts to keep the community local and authentic.

MEDIA PIPELINE

Cloudinary API

Handled client-side image compression, automatic WebP generation, and responsive delivery for low-bandwidth mobile connections.

REFLECTIONS

What I learned from this first project

Managing Real-Time State

Handling live Firestore listeners without causing unnecessary re-renders or exceeding free-tier document read quotas taught me how to architect efficient caching and data streams.

Ephemeral Data Cleanup

Building a 24-hour expiration system required managing TTL timestamps and structuring queries so expired documents were filtered out instantly and cleaned up systematically.

Building for Real Campus Users

Watching classmates actually use the app during exam weeks helped me see what worked and what was confusing, shaping how I approach user experience today.
